 一、选题的目的和意义

当前大学生就业市场竞争激烈，应届毕业生普遍缺乏求职实战经验，在简历撰写、面试表现两大核心环节存在突出问题：简历难以凸显个人核心竞争力，面试因紧张、技巧不足导致发挥失常；线下专业求职指导成本高昂，无法满足应届生即时性、个性化的指导需求。

本项目设计并实现 AI 驱动的全流程求职赋能平台，针对高校毕业生痛点提供免费服务，将简历制作时长大幅缩短，压缩面试准备周期，有效降低学生求职成本，预期提升简历筛选通过率与面试成功率。项目采用 DeepSeek 大模型 API、面部识别技术，结合前后端分离 Web 架构，探索 AI 技术在高校就业服务领域的落地应用，为提升毕业生就业能力提供技术解决方案，具备实践价值与行业示范意义。

通过本项目的全流程开发，我系统掌握 Django DRF 后端开发、Vue3 前端设计、MySQL 数据库建模、异步任务处理、AI 接口集成等核心技术，全面锻炼全栈开发与工程实践能力，为软件工程专业学习与职业发展奠定坚实基础。

 二、主要研究内容

1. 系统架构与技术选型研究：确定前后端分离架构，前端采用 Vue3 + Vite + Element Plus，后端采用 Django + Django REST Framework，数据库为 MySQL 8.0，缓存与任务队列采用 Redis + RabbitMQ + Celery 方案，集成 DeepSeek 大语言模型 API 与 face-api.js 面部识别库，保证系统高效稳定运行。

2. 核心功能模块设计与实现：
	(1) 用户与认证系统：实现用户注册登录、邮箱注册、密码加密存储，基于 JWT Token 完成身份认证与会话管理。
	(2) AI 模拟面试系统：实现多风格 AI 面试官、岗位题库匹配、实时面部表情识别、语音转文字、面试答题流式推送（SSE）、面试中断恢复、实时应答反馈功能。
	(3) 智能评估报告生成：实现多维能力可视化、情绪波动分析、STAR 法则评估、参考答案优化，通过 Celery 异步生成报告。
	(4) 简历智能生成与优化：实现 OCR 简历解析、对话式 AI 生成、模板切换、增量优化、多维度评分、中英双语简历生成。
3. 辅助功能模块：开发个人成长看板、AI 参数自定义配置、实时通知中心、博客社区等功能，完善系统交互体验；基于 Electron headless BrowserWindow 实现简历 A4 精确分页 PDF 导出与逐页预览。
4. 数据库设计：完成 MySQL 数据库表结构设计、关联关系建模与索引优化。
5. 技术保障与性能优化：遵循 RESTful 规范设计 API 接口，自动生成 Swagger 文档；优化接口响应速度与异步任务执行率。

 四、存在的问题和解决办法

1. OCR 简历解析准确率不足。对于多栏布局、图文混合等复杂排版的简历，PaddleOCR 结构化信息提取容易出现偏差，需要人工二次修正，降低了使用效率。

解决办法：优化 PaddleOCR 预处理流程，对图片进行灰度化、去噪、二值化等预处理操作；研究 PP-OCRv5 模型参数调优，提升复杂排版识别准确率；参考开源简历解析项目优化结构化提取逻辑；设计可视化手动修正界面，降低用户修改成本；主动请教指导老师，结合相关技术文献改进解析策略。

2. AI API 调用成本较高且存在响应延迟。面试问答、简历优化等功能需要频繁调用大模型接口，Token 消耗量大，同时网络请求存在延迟，影响用户使用体验。

解决办法：为高频请求增加缓存机制，避免重复调用接口；精简优化提示词内容，压缩无效文本，减少 Token 消耗；依托 Celery 异步任务处理 AI 分析内容，弱化延迟感知；合理规划调用配额，平衡使用成本与系统性能。

3. 面部识别精度不足、设备兼容性差。当前采用的 face-api.js 库在不同浏览器、不同设备以及复杂光线环境下，情绪识别效果不稳定，检测精度波动较大。

解决办法：学习 YOLO 人脸识别模型部署方案，后续替换升级识别模型，提升检测精度；针对多终端、多浏览器做适配优化，解决兼容问题；开展多环境测试，调整识别参数，提升功能运行稳定性。

4. WebSocket 并发运行稳定性欠缺。多人同时在线开展模拟面试时，长连接通信容易出现卡顿、延迟甚至断连问题，无法满足多用户并发使用需求。

解决办法：优化 Django Channels 配置参数，提升服务并发承载能力；增加心跳检测与重连机制，保障实时通信长效稳定；进行压力测试，排查代码缺陷与性能瓶颈，针对性修复漏洞。
