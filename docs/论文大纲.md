# AInterview 平台毕业论文大纲

---

## 摘要

**要素要求**（需回答三个核心问题）：
1. **为什么做**：就业市场竞争激烈，应届生缺乏求职实战经验，简历难以凸显核心竞争力，面试因紧张/技巧不足导致发挥失常；线下专业求职指导成本高昂，无法满足应届生即时性、个性化的指导需求
2. **怎么做的**：前后端分离 Web 架构（Vue3 + Vite + Django DRF），集成 DeepSeek 大模型 API 驱动 AI 面试与简历生成、face-api.js 面部表情识别（7 种情绪）、Web Speech API 语音转文字、PaddleOCR 简历文件解析、SSE 流式追问推送、WebSocket + Django Channels 实时对话、Celery + RabbitMQ 异步报告生成、Electron headless Chromium A4 PDF 导出
3. **结果怎么样**：完成 AI 模拟面试全流程闭环（出题→答题→反馈→追问→报告）、简历智能生成与诊断（OCR 解析→AI 对话→模板→导出）、博客社区等辅助功能；核心功能端到端已跑通，已识别 OCR 精度、API 成本、面部识别兼容性等问题并给出改进方案

**格式要求**：1.5 倍行距，英文关键词格式 `Keywords: AI Interview, Django DRF, Vue3, DeepSeek, face-api.js`

## 第二章 相关技术与理论

### 2.1 前端技术
- Vue3 框架（Composition API、响应式系统、Vite 构建）
- Element Plus 组件库
- TypeScript 类型系统
- Pinia 状态管理
- 选型理由与对比分析（vs React、Angular）

### 2.2 后端技术
- Django 框架（MVT 模式、ORM、中间件）
- Django REST Framework（RESTful API、序列化、视图集、分页、认证）
- Simple JWT 身份认证机制
- drf-spectacular（Swagger 文档自动生成）
- 选型理由与对比分析（vs Spring Boot、Flask）

### 2.3 数据存储与异步任务
- MySQL 8.0 关系型数据库（索引优化、utf8mb4）
- Redis 缓存与 Channel Layer
- Celery 分布式任务队列 + RabbitMQ 消息中间件
- Celery Beat 定时任务调度
- 技术选型理由与优缺点分析

### 2.4 AI 大语言模型接口
- DeepSeek 大模型 API（OpenAI 兼容接口）
- Prompt Engineering 在本项目中的应用：
  - 角色定义（面试官、职业规划师、技术专家）
  - 意图分类（9 维分类：intent/action/scope/section_hint/output_type/complexity/needs_clarification/language/mode）
  - 增量更新（只返回变化部分，不重写全文）
  - 结构化 JSON 输出
- Token 优化策略
- 模型选型理由与优缺点分析

### 2.5 面部识别与语音识别
- face-api.js 面部表情识别（TinyFaceDetector + FaceExpressionNet，7 种基础情绪：中性、开心、悲伤、惊讶、恐惧、厌恶、愤怒）
- 1 秒采样间隔的前端实时检测流程
- Web Speech API 语音转文字（浏览器兼容性、实时转录、累积处理）
- 识别精度与设备兼容性分析

### 2.6 实时通信技术
- SSE（Server-Sent Events）：单向流式推送，用于面试追问推送
- WebSocket + Django Channels：双向全双工通信，用于 AI 对话与用户聊天
- Redis Channel Layer：跨进程消息分发
- SSE 与 WebSocket 的技术选型对比（适用场景、复杂度、资源消耗）

### 2.7 文档解析与 PDF 导出技术
- PaddleOCR 引擎（文本检测 + 识别 + 方向分类器，PP-OCR 模型，扫描件 OCR 回退）
- pdf2image：PDF → 图片的预处理转换（200 DPI，JPEG 格式）
- Electron Headless BrowserWindow + Chromium printToPDF 原生分页
- A4 精确尺寸控制（210mm×297mm，页眉页脚模板，自定义边距）
- Node.js HTTP 微服务架构（端口 9999）

#### 4.3.1 用户认证流程

>

#### 4.3.2 AI 模拟面试流程

> **[插图位置] 图4.4 AI 模拟面试流程图**
>
> **图内容说明**：
> - 使用标准流程图符号，这是论文中最重要的流程图，需绘制详细
> - 主流程：
>   1. 开始 → 用户选择岗位/难度/题数
>   2. 创建 InterviewSession（status=pending）
>   3. 用户点击"开始面试"→ status 变为 running，记录 started_at
>   4. AI 生成第一道题（调用 DeepSeek API，Prompt 含岗位+简历上下文）→ 返回题目 JSON
>   5. 前端展示题目，用户选择答题方式 → [判断] 文本 or 语音？
>      - 语音分支：启动 Web Speech API 监听 → 实时转录累积 → 停止录音 → 获得完整文本
>      - 文本分支：用户在文本框输入
>   6. 同时：face-api.js 持续采样（1s 间隔）→ 记录每帧情绪数据到 analysis_data
>   7. 用户提交回答 → AI 生成即时反馈（Prompt 含岗位+题目+回答）→ 返回反馈 JSON
>   8. [判断] 是否还有剩余题目？
>      - 是 → AI 生成追问（SSE 流式推送，Prompt 含历史对话上下文）→ 回到步骤 5
>      - 否 → 面试完成
>   9. status 变为 finished，记录 finished_at
>   10. 自动触发 Celery 异步任务（generate_interview_report）→ 后台生成报告 JSON → 存入 InterviewSession.report
>   11. 前端跳转报告详情页 → 结束
> - 异常分支：用户中途退出 → status 保持 running → 下次登录路由守卫检测未完成面试 → 弹窗确认 → 恢复面试（回到步骤 5，保留已答题记录）
> - 超时分支：Celery Beat 定时任务每 15 分钟扫描 → status=running 且 updated_at > 30min → 自动标记为 canceled

#### 4.3.3 简历生成与诊断流程

> **[插图位置] 图4.5 简历生成与诊断流程图**
>
> **图内容说明**：
> - 两条入口分支，汇聚到编辑→诊断→导出
> - **入口 A — 文件上传**：上传 PDF/图片 → [判断] 文件类型 → PDF → pdf2image 转图片 → PaddleOCR 文本识别 → 解析文本 → 创建 Resume（status=parsed）
> - **入口 B — AI 对话生成**：用户与 AI 对话 → 前端发送对话历史 → 后端调用 DeepSeek（简历对话 System Prompt，含 6 种 Mode：generate/optimize/style/review/section/chat）→ AI 分类意图 → 增量更新 instructions → 前端应用 instructions 修改简历 JSON → 创建/更新 Resume

> - **诊断分支**：用户输入 JD 文本 → 调用 DeepSeek API（诊断 Prompt）→ 返回评分 + 维度分析 + 修改建议 → 展示诊断报告

#### 4.3.4 实时通信流程

> **[插图位置] 图4.6 实时通信架构图**
>
> **图内容说明**：
> - 左右对比结构：左侧 SSE 流程，右侧 WebSocket 流程

>   - Redis Channel Layer：group_add → group_send → broadcast 到同组所有连接
>   - 标注：双向全双工、持久连接、心跳检测

### 5.1 用户认证模块实现

- **密码安全**：Django AbstractUser 内置 PBKDF2 哈希加密，REST_AUTH.USE_JWT = True 启用 JWT 模式

### 5.2 AI 模拟面试模块实现

- **面试会话状态机**：使用 InterviewSession.Status 枚举（pending → running → finished / canceled）。API 层：POST 创建会话（status=pending）→ 前端进入面试房间 → status 自动切 running → 用户答题 → 完成后 POST /finish → status 切 finished → 触发 Celery 报告生成。超时 30min 由 Celery Beat 定时任务自动标记 canceled

- **AI 动态出题设计**：构造 System Prompt（角色："顶尖公司的资深技术面试官，以提问精准、深入、专业著称"），User Prompt 含岗位名+简历摘要+面试难度+已出题目历史。要求 AI 返回 JSON `{"question": "题目文本"}`。首题为自我介绍类开放性题目，后续题目根据历史回答深度追问

- **追问机制**：维护完整对话历史 `[{question, answer}, ...]`，在每轮追问时将所有历史对话注入 Prompt，AI 基于上下文提出有深度的下一个问题。使用 SSE（Server-Sent Events）实现流式推送，前端 EventSource 监听，后端 Django 视图设置 `Content-Type: text/event-stream`，逐块 yield 文本

- **AI 对话实时通信**：WebSocket + Django Channels 实现。ChatConsumer 生命周期：connect 时 JWT 认证 → 根据对话双方 ID 生成房间组名 `chat_{min_id}_{max_id}` → 加入 Redis Channel Layer 房间组 → receive 处理 3 种消息类型（chat_message / typing_indicator / read_messages）→ 持久化 Message 到数据库 → group_send 广播到房间内所有连接 → disconnect 时离开房间组

- **面部表情实时检测**：useFaceApi composable 封装。初始化：加载 TinyFaceDetector + FaceExpressionNet 模型 → 开启 requestAnimationFrame 循环（1s 间隔）→ 从 `<video>` 元素获取当前帧 → faceapi.detectSingleFace() 检测人脸 → 提取 7 种情绪分数 → 存入 InterviewQuestion.analysis_data 数组（每元素含 timestamp + angry/disgusted/fearful/happy/neutral/sad/surprised 分数）→ 前端同步渲染情绪实时面板

- **语音转文字**：useSpeechRecognition composable 封装。检测浏览器 `SpeechRecognition` / `webkitSpeechRecognition` API → new SpeechRecognition() 配置（lang='zh-CN', continuous=true, interimResults=false）→ onresult 回调获取 transcript → 累积文本由父组件管理（非 composable 内部累积，避免重复追加 bug）

- **面试中断恢复**：路由守卫 `router.beforeEach` 中调用 `checkUnfinishedInterviewApi()` → 后端查询当前用户 status=running 的最新会话 → 前端弹窗确认 → 跳转 InterviewRoom 恢复。恢复时保留已答题记录（InterviewQuestion 数据仍在数据库中），继续未完成的题目

### 5.3 智能评估报告模块实现

- **异步报告生成流程**：面试结束时前端调用 POST /finish → 后端 status 切 finished → `generate_interview_report.delay(session_id)` 发送 Celery 任务到 RabbitMQ → Celery Worker 消费任务 → 调用 DeepSeek API（System Prompt："顶级的职业规划师和面试分析专家……"，User Prompt 含简历摘要+完整面试对话+每道题情绪数据）→ AI 返回 JSON 报告 → 写入 InterviewSession.report 字段 → 前端轮询或 WebSocket 通知报告就绪

- **ECharts 绑定方法**：前端 ReportDetail.vue 挂载时从 report JSON 解析数据 → 初始化 ECharts 实例（基于 DOM 容器 `ref`）→ setOption() 绑定：
  - 雷达图（radar type）：5 项能力维度（沟通表达、逻辑思维、专业知识、应变能力、综合素质），每项 0-100 分，从 report 的 `dimension_scores` 提取
  - 折线图（line type）：X 轴时间线，Y 轴 7 种情绪分数（7 条不同颜色曲线），从每道题的 `analysis_data` 数组汇总

- **STAR 法则评估 Prompt**：要求 AI 对每道题的答题内容按 S（情境）、T（任务）、A（行动）、R（结果）四个维度分别评分，指出缺失维度并给出 STAR 格式的参考答案。参考答案缓存到 Redis（key=`reference_answer:{question_id}`，TTL=1h）

### 5.4 简历生成与管理模块实现

- **PaddleOCR 解析流程**：用户上传 PDF → 后端 pdf2image.convert_from_path(dpi=200) 逐页转换 JPEG → PIL Image 写入临时文件 → PaddleOCR.ocr(tmp_path, cls=True) 调用文本检测+识别+方向分类 → 过滤低置信度结果（<0.5）→ 合并各页文本 → 创建 Resume（parsed_content=提取文本，status='parsed'）。图片上传直接 OCR，不经过 pdf2image

- **AI 对话式简历生成**：核心是简历对话 System Prompt（Classifier + Router 模式）。AI 每次先分类用户意图（9 维：intent/action/scope/section_hint/output_type/complexity/needs_clarification/language/mode）→ 再根据 Mode（generate/optimize/style/review/section/chat）执行对应行为策略 → 返回 JSON 含 `classification` + `instructions` + `message`。前端按 instructions 数组逐条执行 resumeData 的增量修改（content 的 Markdown 全文或 patch，customStyles 的增量 CSS）。优化模式（optimize）下只返回变化部分，不重写全量 content

- **模板系统架构**：双层 CSS 覆盖机制。第一层 themeStyles：用户选模板时整体替换，AI 不修改。第二层 customStyles：AI 和用户的自定义样式，排列在 themeStyles 后自然覆盖。AI 的 style mode 只返回被修改的选择器和属性，不重复 themeStyles 已有规则

- **JD 匹配诊断**：System Prompt 定为"顶级的职业规划导师和资深技术招聘官"。输入简历 JSON + JD 文本 → AI 返回 JSON（3 个维度评分：技能匹配、经验匹配、教育匹配，overall_score 0-100，strengths/weaknesses/suggestions 各含 3-5 条具体内容）

- **Electron PDF 导出流程**：前端 useExport composable → 将 resumeData + themeStyles + customStyles 渲染为完整 HTML 字符串 → POST http://localhost:9999/api/pdf → Electron main.js 接收 → 写入临时 .html 文件 → 隐藏 BrowserWindow 加载 file:// URL → 轮询检测 `.resume-document` 元素渲染完成 → webContents.printToPDF()（pageSize: {width: 210000, height: 297000} 微米单位，margins: custom，displayHeaderFooter: true，headerTemplate/footerTemplate 含简历名和页码）→ 返回 PDF Buffer → 前端 createObjectURL + a 标签触发下载

## 第七章 总结与展望

### 7.1 工作总结
- 完成 Django 项目框架搭建，11 个应用模块（9 个含完整业务模型）
- 实现 AI 模拟面试全流程（出题→答题→反馈→追问→报告，端到端闭环）
- 实现简历智能生成与管理（OCR 解析→AI 对话→模板切换→JD 诊断→PDF 导出）
- 实现辅助功能（操作日志、博客社区、个人看板、AI 参数配置）
- 技术收获：Django DRF 全栈开发、DeepSeek API Prompt Engineering、Django Channels 实时通信、Celery 异步任务、Electron 桌面开发

### 7.2 存在的不足
1. OCR 解析准确率不足（多栏布局、图文混合简历偏差大）
2. AI API 调用成本较高且存在响应延迟
3. 面部识别精度在不同设备/光线环境下不稳定
4. WebSocket 多用户并发长连接稳定性欠缺
5. ActivityLog 已读标记未持久化（mark-as-read 接口为占位实现，is_read 始终为 false）
6. 全项目测试用例尚未编写（测试框架已搭建，用例待补充）
7. 社交通知自动触发未实现（Notification 模型已定义，信号机制待开发）
8. AI 面试官为单一固定角色，缺少多风格切换

### 7.3 未来展望
- 升级人脸识别模型（YOLO/MTCNN 替换 face-api.js，提升精度与兼容性）
- 生产环境部署（Docker 容器化 + Nginx HTTPS + 云服务器 + CI/CD）
- 全站移动端响应式适配
- 多风格 AI 面试官（严格型/温和型/压力型可切换）
- 社交通知系统完善（Django Signals 自动触发 + 邮件/站内推送）
- 社区功能扩展（文章推荐算法、热门排序、全文搜索）
- WebSocket 并发优化（连接池、心跳重连、压力测试、水平扩展）
