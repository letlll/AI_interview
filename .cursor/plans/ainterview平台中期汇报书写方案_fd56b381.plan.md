## 模块二：选题的目的和意义

### 书写模板（4 点框架）：

**1. 实际需求层面：**

> 当前大学生就业市场竞争激烈，应届毕业生普遍缺乏求职实战经验，尤其是简历撰写和面试表现两大核心环节面临突出困境：简历难以凸显个人核心竞争力，面试时紧张情绪和应答技巧不足导致表现失常，而线下专业指导资源成本高昂（500-2000元/次），难以满足大量应届生的即时性、个性化需求。

**2. 应用价值层面：**

> 平台以 AI 技术驱动全流程求职赋能，将简历制作时间从平均 8 小时压缩至 1 小时，面试准备周期从 2 周缩短至 3 天，基础功能全免费，可替代线下高成本面试培训，节省学生 80% 求职成本，同时提升简历筛选通过率（预期 50%）和面试通过率（预期 25%）。

**3. 技术与行业趋势层面：**

> 借助成熟的商业化大语言模型 API（如 DeepSeek）和前端面部识别技术（face-api.js），结合前后端分离的现代化 Web 架构，探索 AI 技术在就业服务领域的实际应用，为高校毕业生就业能力提升提供技术解决方案，具有良好的行业示范效应。

**4. 个人能力培养层面：**

> 通过本项目的完整开发过程，系统掌握 Django REST Framework 后端 API 开发、Vue3 前端交互设计、MySQL 数据库建模、异步任务处理（Celery）、AI API 集成与前后端联调等核心技术，锻炼软件工程全栈开发能力和问题解决能力。

## 模块三：主要研究内容

### 书写模板（按 4 大板块分层）：

**1. 系统架构与技术选型研究**

> 确定系统采用前后端分离架构，前端选用 Vue3 + Vite + Element Plus 技术栈，后端选用 Django + Django REST Framework，数据库采用 MySQL 8.0，缓存与任务队列采用 Redis + RabbitMQ + Celery 方案，AI 能力依托 DeepSeek 商业化大语言模型 API 和 face-api.js 面部识别库，实现系统的稳定、高效与可维护。

**2. 核心功能模块设计与实现**

**(1) 用户与认证系统**

- 用户注册登录（含手机号/邮箱验证、密码加密存储）
- GitHub OAuth 第三方登录
- JWT Token 身份认证与会话管理

**(2) AI 模拟面试系统**

- 多风格 AI 面试官（技术专家 / 业务导向 / 压力测试 / 友好引导）
- 岗位专属题库匹配（覆盖 7+ 行业、20+ 岗位）
- 实时面部表情识别（face-api.js 检测 7 种基础情绪）
- 语音转文字录入（实时将用户回答转为文字）
- WebSocket 实时双向通信（Django Channels）
- 面试中断无缝恢复（会话状态持久化）
- 实时反馈机制（语速异常、口头禅、关键词缺失提示）

**(3) 智能评估报告生成**

- 多维能力雷达图（技术深度、逻辑思维等 8 项）
- 情绪波动曲线可视化
- STAR 法则回答分析
- 参考答案对比与改进建议
- Celery 异步任务队列保障报告生成（≤30秒）

**(4) 简历智能生成与优化**

- OCR 简历上传解析（提取结构化信息）
- 对话式 AI 生成简历（Markdown 编辑器，支持拖拽模块）
- 10 套行业模板一键切换
- AI 增量优化（避免全量重写，信息保留率≥95%）
- 多维度评分系统（内容质量、结构、语言、ATS 友好度，满分 100）
- 中英双语简历一键生成

**3. 辅助功能模块**

- 个人成长看板（面试次数、通过率趋势、能力雷达图历史对比）
- 博客/问答广场（Markdown 编辑，点赞/评论/收藏）
- 实时通知中心（WebSocket 推送站内消息）
- AI 参数自定义配置（用户可选模型和 API Key）

**4. 技术保障与性能优化**

- Docker Compose 一键部署（Nginx + Uvicorn）
- API 接口规范化（RESTful 设计，Swagger 文档自动生成）
- 数据安全与隐私保护（HTTPS 传输、视频存储≤7 天）

## 模块五：存在的问题和解决办法

### 书写模板（一一对应，具体到技术点）：


| 存在的问题                                                                                        | 解决办法                                                                                                                                                                                                                                 |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **问题 1：face-api.js 表情识别准确率不稳定**——在低光照或侧脸角度下，7 种基础情绪识别准确率难以稳定达到预期的 85% 基准，存在误检和漏检情况           | 1. 在面试房间前端页面增加光线检测提示，引导用户在光线充足环境下进行面试；2. 参考 face-api.js 官方示例优化检测参数（如调低 minConfidence 阈值增加召回）；3. 查阅 GitHub 上同类项目的参数调优方案（如面试 AI 项目的 face-api 配置）；4. 考虑引入多帧融合策略提高稳定性                                                                    |
| **问题 2：WebSocket 实时通信稳定性不足**——面试过程中 Django Channels WebSocket 连接偶发中断，面试会话状态丢失，影响用户体验和评估数据完整性 | 1. 学习 Django Channels 官方文档中的连接管理机制，增加心跳检测（heartbeat）保持连接活跃；2. 在前端 useChatMarkdown.ts 中增加断线重连逻辑（WebSocket reconnect），并缓存中断前的回答数据；3. 在后端增加会话状态持久化（interactions 表），确保断线后可恢复；4. 向指导教师请教 Django Channels 生产环境部署注意事项（参考项目已有 nginx 配置）      |
| **问题 3：OCR 简历解析准确率有待提升**——对于复杂排版（如多栏布局、图片内嵌文字）的简历，OCR 解析后结构化信息提取存在偏差，需要较多人工修正                | 1. 学习 Tesseract OCR 参数调优方法，尝试多种预处理方案（灰度化、二值化、去噪）；2. 参考 GitHub 上成熟 OCR 简历解析开源项目（如 Resume-Parser）的处理流程；3. 设计用户友好的修正界面，让用户在解析结果上进行微调而非全手工重填；4. 在简历 AI 生成流程中增加 OCR 结果的置信度提示，引导用户优先修正低置信度字段                                               |
| **问题 4：DeepSeek API 调用成本与响应速度优化**——简历增量优化和面试问答分析涉及大量 API 调用，存在 Token 消耗较大和响应延迟问题，影响用户体验      | 1. 在 resumes/resume_chat_view.py 和 interviews/ai_services.py 中增加请求缓存机制，相同问题短时间内不重复调用 API；2. 优化 Prompt 设计，减少不必要的 Token 消耗（如精简 system prompt、限制回复长度）；3. Celery 异步任务队列已接入，将 AI 分析任务从同步改为异步，用户无需等待即时响应；4. 考虑实现 Token 用量统计与用户配额管理，平衡成本与体验 |
| **问题 5：前后端联调效率低，接口文档不完善**——部分 API 接口前后端字段命名不一致，Swagger 文档注释不够详细，导致联调返工较多                     | 1. 在所有 serializers.py 和 views.py 中补充 DRF 字段级注释（help_text），完善 Swagger 文档；2. 使用 Pytest 编写接口测试用例，提前验证 API 响应格式；3. 在前端 axios 封装中增加请求/响应拦截器，统一处理错误和字段映射；4. 建立前后端接口约定文档（README 或 API.md），明确字段命名规范                                          |
